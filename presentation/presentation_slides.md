### [สไลด์ที่ 3] สถาปัตยกรรมระบบภาพรวม (System Architecture Flow)
* **ผู้พูด:** คนที่ 6
* **หัวข้อสไลด์:** End-to-End System Pipeline (การทำงาน 4 ขั้นตอน)
* **เนื้อหาสำคัญ (ไดอะแกรม 4 กล่อง):**
  1. **Input Layer:** รับรูปถ่ายตู้เย็น (Image Upload / Drag & Drop) หรือข้อความพิมพ์
  2. **Extraction Layer:**
     * *รูปภาพ:* ส่งเข้าโมเดล YOLOv8 เพื่อสกัดตำแหน่ง Bounding Box และชื่อวัตถุดิบ
     * *ข้อความ:* ส่งเข้าตัวตัดคำและแปลง Synonym Mapping ภาษาไทย
  3. **Core ML Layer:** นำวัตถุดิบมาตรฐาน 12 ชนิดเข้าโมเดลคำนวณ (Weighted Cosine Similarity / KNN) เทียบกับฐานข้อมูลสูตรอาหาร 50 เมนู
  4. **Output Layer:** จัดอันดับเมนูอาหาร แสดง % ความพร้อม วัตถุดิบที่ขาด และวิธีทำแบบทีละขั้นตอน
* **จุดเน้น:** วัตถุดิบทุกชนิดจะถูกแปลงเป็น **Normalized Data Contract 12 ชนิด** ทำให้ส่วนประกอบทุกชิ้นของเพื่อนในกลุ่มเชื่อมเข้าหากันได้อย่างราบรื่น

### [สไลด์ที่ 4] การจัดเตรียมชุดข้อมูลรูปภาพ (Image Dataset Preparation)
* **ผู้พูด:** คนที่ 1
* **หัวข้อสไลด์:** การเก็บข้อมูลและเตรียมภาพถ่ายวัตถุดิบ 12 คลาส
* **เนื้อหาสำคัญ (Bullet Points):**
  * **การเก็บข้อมูลจริง (Data Collection):** ถ่ายภาพวัตถุดิบสดทั้งในตู้เย็น บนโต๊ะครัว และซูเปอร์มาร์เก็ต รวม 12 คลาส:
    * *โปรตีน:* หมูสับ, อกไก่, กุ้งสด, เบคอน, ไข่ไก่
    * *แป้ง:* ข้าวสวย, เส้นพาสต้า, ขนมปัง
    * *ผัก/นม:* ใบกะเพรา, มะเขือเทศ, ชีส, ผักกาดขาว
  * **การทำ Data Labeling บน Roboflow:** ตีกรอบ Bounding Box กำหนดพิกัดวัตถุดิบทุกรูป
  * **Data Augmentation:** เพื่อเพิ่มความทนทานต่อสภาพแสงในตู้เย็น:
    * หมุนภาพ (-15 ถึง +15 องศา)
    * ปรับความสว่าง (Brightness +/- 20%)
    * ขยายชุดข้อมูลจาก 400 ภาพ กลายเป็นกว่า 1,200 ภาพ
  * **การแบ่ง Dataset:** Train (70%), Validation (20%), Test (10%)

### [สไลด์ที่ 5] การเทรนโมเดลตรวจจับวัตถุดิบ (Computer Vision Model)
* **ผู้พูด:** คนที่ 2
* **หัวข้อสไลด์:** การฝึกสอนโมเดลตรวจจับภาพ (YOLOv8 Object Detection)
* **เนื้อหาสำคัญ (Bullet Points):**
  * **การเลือกสถาปัตยกรรม:** เลือกใช้ **YOLOv8 Nano (YOLOv8n)** เพราะขนาดโมเดลเล็ก (<10MB) ประมวลผลได้เร็ว เหมาะกับการรันบน Web API
  * **สภาพแวดล้อมในการเทรน:** Google Colab (Tesla T4 GPU), Epochs: 50, Batch size: 16
  * **ผลการวัดประสิทธิภาพ (Performance Metrics):**
    * Mean Average Precision (mAP@0.5): **89.4%**
    * Precision: **88.2%** | Recall: **86.7%**
    * Inference Speed: **~18 ms ต่อภาพ** บน GPU (และ ~120 ms บน CPU)
  * **ภาพประกอบในสไลด์:** ใส่ภาพกราฟ F1-Confidence Curve, Confusion Matrix และตัวอย่างภาพตู้เย็นที่มีกรอบ Bounding Box สีเขียวตีกรอบหมูสับ/ไข่ไก่

### [สไลด์ที่ 6] การประมวลผลข้อความภาษาไทย (Text Processing & NLP)
* **ผู้พูด:** คนที่ 4
* **หัวข้อสไลด์:** การสกัดชื่อวัตถุดิบจากข้อความพิมพ์ของผู้ใช้
* **เนื้อหาสำคัญ (Bullet Points):**
  * **ปัญหาของข้อความธรรมชาติ (Unstructured Text):** ผู้ใช้มักพิมพ์คำพูดไม่เหมือนกัน เช่น *"มีหมูบด 2 ขีด"*, *"เหลือไข่ 3 ฟอง"*, *"มีเส้นสปาเก็ตตี้"*
  * **กระบวนการจัดการข้อมูล (Text Preprocessing Pipeline):**
    1. *Cleaning:* ลบตัวเลข, หน่วยนับ (ฟอง, ขีด, กิโล) และสัญลักษณ์พิเศษ
    2. *Stopword Removal:* ตัดคำฟุ่มเฟือย เช่น 'มี', 'เหลือ', 'ในตู้เย็น', 'และ'
    3. *Synonym Mapping (พจนานุกรมคำพ้อง):*
       * หมูบด / หมูชิ้น ➔ **หมูสับ**
       * สปาเก็ตตี้ / มักกะโรนี ➔ **เส้นพาสต้า**
       * แฮม / ไส้กรอก ➔ **เบคอน**
  * **ผลลัพธ์:** ได้ Normalized Ingredient List ตรงตามมาตรฐาน 12 คลาส พร้อมส่งเข้าโมเดลคำนวณ

### [สไลด์ที่ 8] การทดลองและเปรียบเทียบโมเดล Machine Learning (Candidate Models Comparison)
* **ผู้พูด:** คนที่ 5 (Core Recipe ML)
* **หัวข้อสไลด์:** การทดลองและเปรียบเทียบประสิทธิภาพ 3 อัลกอริทึม สำหรับระบบแนะนำสูตรอาหาร
* **ภาพประกอบสไลด์:** `presentation/model_comparison_chart.png` (ชาร์ตเปรียบเทียบความแม่นยำและเวลาประมวลผล)

* **ตารางเปรียบเทียบ 3 โมเดล (Detailed Model Comparison Table):**

| มิติการเปรียบเทียบ | 1. KNN (K-Nearest Neighbors) | 2. TF-IDF Vectorizer | 3. Random Forest Classifier |
| :--- | :--- | :--- | :--- |
| **หลักการทำงาน (Mechanism)** | วัดระยะห่างเวกเตอร์วัตถุดิบ (Cosine Distance) ใน Multi-label Space | แปลงข้อความ/วัตถุดิบเป็นเวกเตอร์ความถี่ และถ่วงน้ำหนักคำสำคัญ | Ensemble Decision Trees เรียนรู้กฎความสัมพันธ์ของชุดวัตถุดิบ |
| **Top-1 Accuracy** | **90.0%** | 86.0% | **92.0%** |
| **Top-3 Accuracy** | **100.0%** | 94.0% | 96.0% |
| **Precision / Recall / F1** | 89.2% / 87.0% / 88.1% | 91.5% / 88.6% / 90.0% | **92.8% / 91.0% / 91.9%** |
| **Inference Latency** | 2.15 ms | **1.48 ms (เร็วที่สุด ⚡)** | 4.35 ms |
| **Cold-Start Performance** | ปานกลาง (ต้องมีประวัติเวกเตอร์) | ดีเยี่ยม (รับคำค้นหาใหม่ได้ทันที) | ต่ำ (ขึ้นกับ Feature กฎต้นไม้เดิม) |
| **ความโปร่งใส (Explainability)** | สูง (อธิบายจากระยะห่างที่ใกล้ที่สุด) | สูงมาก (เห็นน้ำหนักคะแนนของแต่ละคำ) | ปานกลาง (Black-box tree rules) |
| **จุดเด่นสำคัญ (Key Strength)** | แนะนำเมนูใกล้เคียงได้ธรรมชาติ เมื่อมีของไม่ครบ | ตอบสนองไวที่สุด กินทรัพยากรน้อย เหมาะกับคำค้นสั้น | แม่นยำสูงสุดในการจัดกลุ่มสูตรอาหารที่มีโครงสร้างซับซ้อน |
| **ข้อจำกัด (Limitation)** | ประสิทธิภาพลดลงถ้าข้อมูลมีมิติสูง (Curse of Dimensionality) | ไม่เข้าใจลำดับความสำคัญของวัตถุดิบหลัก vs รอง | ใช้เวลา Inference นานกว่า และขนาดโมเดลใหญ่กว่า |

* **ประเด็นสรุปสำหรับนำเสนอ (Key Takeaways):**
  1. **ด้านความแม่นยำ:** Random Forest ทำ F1-Score ได้สูงสุดที่ 91.9% แต่ KNN ชนะในด้าน Top-3 Accuracy ที่ 100% (แนะนำ 3 เมนูติดเมนูที่ต้องการแน่นอน)
  2. **ด้านความเร็ว (Latency):** TF-IDF Vectorizer ใช้เวลาเพียง 1.48 ms เร็วที่สุดเนื่องจากเป็นการคูณ Matrix ทางคณิตศาสตร์โดยตรง
  3. **การนำไปใช้งานจริง:** ทั้ง 3 โมเดลถูกผนวกเป็นตัวเลือก (Model Switcher) ในระบบ เพื่อให้ผู้ใช้สามารถทดลองสลับเปรียบเทียบผลลัพธ์แบบ Interactive ได้แบบเรียลไทม์
